# Contributing to OctoFlow

Thank you for your interest in contributing!

---

## 📝 Getting Started

1. **Fork the repo** and clone your fork locally.
2. **Create a branch** for your feature or fix:
   ```bash
   git checkout -b feat/my-new-feature
   ```
3. **Make changes** and write tests if needed.
4. **Commit** and **push** your branch:
   ```bash
   git push origin feat/my-new-feature
   ```
5. **Open a Pull Request** on GitHub ([How to do this](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/creating-a-pull-request)).

---

## 💬 Issues & Discussions

- Found a bug? [Open an issue](https://github.com/DevCoder279/OctoFlow/issues)
- Have an idea or feature request? [Start a discussion](https://github.com/DevCoder279/OctoFlow/discussions)

---

## 🚦 Code Style

- Follow the existing code formatting (Prettier/ESLint).
- Use descriptive commit messages.
- Add clear comments and documentation where needed.

---

## 📋 Pull Request Guidelines

- Describe what you changed and why.
- Link issues in your PR description when relevant.
- Keep PRs focused and minimal for easier reviews.
- Make sure the app builds (`npm run build`) and passes tests locally.

---

## 📝 Code of Conduct

All contributors are expected to adhere to our [Code of Conduct](CODE_OF_CONDUCT.md).

---

Thank you for helping to make OctoFlow better!
